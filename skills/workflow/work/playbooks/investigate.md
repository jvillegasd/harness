# Investigate

**You own the answer.** It is read-only: a cited explanation or a recommendation, never a code change.

1. Run `how` over the subsystem. For a question about motivation, also run `why`. For a claim that needs runtime or external evidence, run `research`.
2. Write the answer in `how`'s shape. When the question is a choice between options, write a recommendation with a tradeoffs table instead.
3. Read `unslop` from its path and apply it to the reply.

No branch and no PR. When the answer leads to a code change, hand it back to the human: the change is a new task, matched again as a bug fix or a feature.

**Reply:** the answer. For "are we sure?", give your real judgment with its reasons, and push back when the premise is wrong.
